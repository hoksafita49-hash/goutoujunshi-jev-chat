# 联系人选择与本次想法

本轮维护 Windows 和 Android 云模式，沿用 PocketBase、统一 API 网关和现有账号。
iOS 及截图/OCR 问题按用户要求暂缓。本次调整联系人归属和生成输入，不增加平台采集能力。

## 使用流程

打开“分析当前对话”，在原文核对页顶部选择本轮联系人。已有可靠关联会预选当前人物，
仍可更换；没有关联时可直接选择已有联系人，不必先去云账号页操作。“新建人物”只先
保留本轮草稿，确认分析时再保存，取消核对不创建联系人。

同一个人在不同平台使用不同昵称时，选择同一个联系人。各平台会话分别保留来源，分析
读取当前会话的确认消息和这个人的已确认记忆，不把其他平台的全部消息自动混入本轮。
更换关联不会移动此前已保存的消息。没有可靠标题时，必须明确选人；本轮单独建会话，
不会把“已确认对话”等占位文字作为长期身份。

“本轮想法”是可选输入，最多 2000 个 Unicode 字符，示例：

> 我现在不困，还想继续聊，但不想显得催促。不要替我说要睡觉。

也可以填写当时的背景、自己知道的事实、希望达成的目标或不想采用的表达。输入与聊天
原文分开保存，不能冒充对方说过的话。先核对原文、说话人和联系人，再确认分析。

## 保存与改写

本轮补充随这次分析的输入快照和本机任务请求保存，不自动写入人物档案、长期记忆、
笔记或风格偏好。新一轮核对默认空白；需要长期使用的偏好仍应去偏好设置编辑。

分析、起草、排序及后续改写/解释都使用相同补充。改写从指定原分析的服务端输入继承，
不会从模型结果或另一轮分析猜测。填写不同想法后提交会区分任务，不能拿到另一份想法
对应的旧回复。网络中断后恢复原任务则继续原来的请求，不自动新建付费请求。

生成规则要求尊重你明确提供的当前状态和目标，不凭空补写睡意、疲惫或结束聊天意愿。
这些约束减少无依据的代写，发送前仍应检查候选是否符合你的真实想法。

## 验证范围

回归检查使用合成聊天、隔离数据库和模型替身；覆盖人物选择/新建取消、旧历史保留、
无标题隔离、请求跨重启恢复、意图缓存区分、原分析继承和原文引用校验。替身测试验证
数据传递和边界，不代表已经证明真实模型对任何表达都会正确理解。

双端安装包、源码和部署验收结果在同次交付记录中列出。保留原有账号和缓存，升级时
不要卸载 Android 应用或清空云账号数据。
