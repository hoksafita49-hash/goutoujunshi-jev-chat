# iOS 云端接入（第一阶段源码）

主 App 的“配置 → 使用统一云服务”提供服务器、邮箱与密码登录，使用服务器预建账号。模型供应商 Key 仅放在服务端。保留的直连模式需用户明确关闭云模式；云失败不会自动改用设备 Key。

服务器根地址仅接受 HTTPS。开发允许 `http://127.0.0.1:18000` 或 `http://localhost:18000` 的本机 SSH 隧道；手机上的 localhost 指手机本身，不是 Windows 电脑。预留域名 `https://api.zovoeh.cn` 需完成 DNS/TLS 和服务部署后才能登录。禁止在 URL 放凭据、查询参数或片段，客户端拒绝 HTTP 重定向。

登录后：

1. 在配置页预览旧人物资料，核对后点“确认导入以上资料到当前账号”。原资料保留；重复导入使用同一迁移映射，同名人物不会自动合并。
2. 在“关系”页新建或选择人物。资料编辑原子写入当前账号 SQLite 的本机编辑层与 outbox，前台与手动同步推送给网关。
3. 在“使用”页手动整理文字或使用 Apple Vision 本地识图，核对双方和当前人物。“仅同步已确认聊天”可以保存而不调用模型；“确认并分析”先完成同步再提交持久任务。
4. 其他端保存的同一人物、已确认聊天、偏好及分析结果在主 App 同步后出现。前台每 15 秒检查；进入后台停止等待，不删除云任务。没有后台即时同步保证。
5. 冲突在配置页展示本机和服务端内容，明确选择采用哪一份。删除墓碑不会被离线修改自动恢复。

分析、解释和改写均走网关任务接口。请求 ID 在联网前持久化，提交响应丢失时只允许手动重试同一个请求 ID；查询任务不会重新调用付费模型。候选保持服务器顺序和 candidate_id，空权重保持为空，相对权重显示为百分数，不显示成功率。新截图、未经确认原文及未完成同步的上下文不能提交键盘云任务。

账号 token 和设备 secret 存在主 App/键盘共享 Keychain；同步库按服务器与用户 ID 隔离。退出会尝试撤销当前设备并清除本机会话及共享快照，保留原账号独立数据库。401 要求重新登录；不自动回退。服务器恢复变更 epoch 时暂停上传并保留原队列，重新登录后可明确选择保存完整 SQLite 恢复副本再重建；旧数据不会自动回灌。

键盘未确认提交结果的请求 ID 按账号保留，退出或重新登录只清可见快照；同账号重新登录后继续查询或使用原 ID 重试，他账号无法读取或执行该请求。会话切换使旧同步任务失效，迟到的错误不会清除新账号凭据。历史分页仅推进自身游标，不把较新的镜像版本降级。

主 App 是同步 SQLite 的唯一写入者，`App/Sync/` 不编入键盘/Capture。键盘有 Full Access 时读取按账号校验的原子 App Group 快照，可对其中已同步的上下文创建和查询云任务，只有任务 ID 使用独立 mailbox 保持重试。键盘不 flush outbox、不写消息库、不假装唤醒后台主 App；新资料、原文和截图在主 App 核对同步。没有 Full Access 时保留普通离线打字。

## 验证和安装

`bash tools/check.sh` 在 macOS 上运行既有核心/打字/图片检查和新增 `Tests/CloudChecks.swift`，包含共用 `contracts/fixtures/`、GET/202/401、账号隔离、SQLite 冲突/墓碑、迁移去重与重复短消息检查。`python tools/check_project.py` 在 Windows 也可检查工程生成结果、SQLite 链接和扩展文件归属；它不能替代 Swift 类型检查。

`.github/workflows/ios-build.yml` 的 macOS runner 执行上述检查和模拟器/未签名设备构建。该 workflow 只提供模拟器开发 ZIP，不能安装到 iPhone。本阶段未提供签名凭据、TestFlight 发布或真机验收；需在远程 macOS/Xcode 构建成功后继续完成 Apple 签名与个人 iPhone 验收。
